# Requested repairs - 2026-09-20

## Delivery and scope

This is the complete `debian-preseed-de` repository, based on the uploaded
`debian-preseed-de(5).zip`, not a patch-only delivery. All 3,128 original files
are retained. No original file is removed. There are 23 changed original files:
17 implementation/staging files, three affected existing test files, and the
three regenerated publication artifacts. Three new runtime assets (two SVGs
and a timer) and a focused regression test are added. This report and its
validation evidence are additional repository documentation.

The rebuilt `d-i/forky/payload.tar.gz` contains 1,380 files. Its manifest and the
payload reference in `preseed.cfg` were regenerated with the repository's own
builder. A second build produced identical bytes for all three artifacts.
The complete outer delivery archive uses deterministic timestamps and standard
0644/0755 file modes; executable status is preserved. No fonts, dependencies,
source builds of labwc/Waybar, or binary replacements are bundled as part of
these repairs. Existing package selections and host profiles are unchanged.

## 1. Native window switcher and process isolation

Both Waybar configurations now launch on **mouse-button release**, rather than
press. This avoids starting labwc's focus override while Waybar still owns the
mouse press. This is the source-based explanation of the reported stuck-button
behavior; it has not been reproduced against the user's live compositor.

The launcher queues a fixed-name, nonblocking transient **user service** with
`systemd-run --no-block --collect`, an absolute executable path, the existing
session dependencies, `ExitType=cgroup`, and `KillMode=control-group`. Startup
and runtime are bounded to three seconds, and stop to one second. Standard
input/output cannot keep a Waybar pipe open; diagnostics go to the journal.

The fixed-argument, non-root wrapper executes:

```
/usr/bin/timeout --signal=TERM --kill-after=1s 2s /usr/bin/wtype -P F13 -p F13
```

F13 goes down and up on the **same virtual keyboard immediately**, not when the
user eventually selects or cancels a window. Therefore the normal switcher
lifetime has no held F13 to clean up. Timeout and service teardown bound a stuck
injector. No modifier-holding daemon, second keyboard device, polling broker,
external window list, or compositor patch was introduced. The existing F13
`NextWindow` binding and Alt+Tab bindings remain native labwc actions.
The old `wtype -k F13` also included a release: this repair does not incorrectly
attribute the symptom to that option holding the key indefinitely.

AppArmor for this wrapper now permits the inherited `timeout` executable and
the narrowly scoped signals used between that wrapper's processes.

## 2. Wayscriber and Applications icon alignment

Only these two icons now use small repository-owned symbolic SVGs in equal
24-by-24 view boxes. GTK centers the painted images, rather than relying on
font side bearings or baselines. Their color, hover gradient/color, dimensions,
internal-display sizing, tooltips, actions and Applications drawer are retained.
The images scale with the configured font size (`1.2em`). The single-space
labels intentionally keep the custom modules visible and interactive.

Both assets are explicitly staged into the desktop skeleton and included in
the payload. The complete rendered CSS was parsed by the real GTK 3 library
and rendered in Xvfb. Background-subtracted pixel bounds for both icons, in
normal and hover states, were centered with zero measured offset in the test
fixture. This is actual GTK rendering, not a live Waybar/labwc session test.

## 3. Custom GRUB and Timeshift

The permanently-true `PathExistsGlob` watcher was replaced with an edge-triggered
`PathChanged=/run/timeshift` watcher. Successful managed snapshot jobs queue a
nonblocking refresh after completion. A new timer reconciles at boot and then
approximately every 15 minutes, covering missed events and GUI-driven changes.
The refresh does not wait for an open Timeshift GUI to exit. Refresh remains a
low-priority, private-mount, bounded oneshot. Existing snapshot schedules and
retention policy were not changed.

The custom GRUB generator now validates its profile inputs and trusted config
ownership/modes, writes its config and generator by same-directory atomic
replacement, and requires `grub-script-check` before publishing the initial
custom menu. A missing/failing checker preserves the last good menu. A missing
snapshot menu is guarded instead of blindly loaded.

Snapshot refresh obtains the effective hardware/profile flags from the same
canonical generator via a read-only `--snapshot-config` export. This avoids a
second, divergent hardware-policy implementation. Missing configuration keys
retain their defaults, duplicates are rejected, and configuration reads are
bounded, no-follow, nonblocking and restricted to trusted regular files.

Refresh uses a private, read-only `nosuid,nodev,noexec` Btrfs top-level mount;
checked, bounded mount/unmount commands; and only its own mount directory for
cleanup. Lock creation rejects unsafe inodes without chmod-ing an existing
shared `/run/lock`. Timed waiting uses a monotonic clock. Snapshot limits are
bounded to 1..200, metadata reads are bounded, incomplete/malformed metadata and
escaping symlinks are skipped, comments are sanitized/quoted, and rootflags
replace complete subvolume selectors without corrupting `@home`-like names.
Debian relative usrmerge links inside the snapshot are accepted; links outside
that snapshot are not. Boot entries use explicit filesystem UUIDs.

Snapshot menus are generated in the destination filesystem, checked before
publication, synchronized and atomically renamed. Identical content does not
rewrite the published menu. Subprocess supervision errors cannot be mistaken
for successful validation. Relevant AppArmor permissions were extended only
for the canonical exporter, its two helper commands and known hardware inputs.

## 4. Firstboot AppArmor denial

Only `managed-firstboot` gains:

```
@{HOME}/.config/systemd/user/ r,
```

There is deliberately no `owner` qualifier: firstboot's filesystem UID is root
while the directory belongs to the desktop user. This grants directory listing
only, not recursive access or write permission. It addresses the exact directory
read reported in the supplied audit records without changing enforcement mode.

### Existing mismatch and incomplete wider runs

The original ZIP itself contains a provenance mismatch for
`d-i/forky/hosts/profiles/btrfs-de-dual-flex.env` in `docs/migration-map.json`.
Its actual SHA-256 is
`01dd669277362f4f8e03c17cd51f697dbfd501ce54a06807e0f845e48a07f3d2`, while the
existing ledger records
`1aeeb84dcab6b422326119611e6caae9d84ed525caf7b259470c6808cc917739`.
Both were left unchanged; no test was weakened to hide the discrepancy.
`baseline-ledger.log` records verification against the untouched uploaded ZIP.

Wider test invocations hit execution time limits while running bootstrap,
audio-supervisor and Btrfs fixture tests. Their partial logs are included and
are **not** reported as successful full-suite runs. An initial direct unit
verification also encountered unrendered unrelated drop-ins and absent target
executables; the isolated verification above avoids loading unrelated templates
without changing production units.

This environment has no live labwc/Waybar/wtype session, GNU `grub-script-check`,
installed Moo/MooX/Types dependency set, bootable target or Btrfs test filesystem.
Consequently no unattended installation, real snapshot restore/boot, live
compositor interaction, or kernel-enforced AppArmor run is claimed. The test-only
Perl adapter and command fixtures are never included in the target payload.

## Publication and target acceptance

Publish the **whole repository** atomically using the existing deployment
procedure. Do not mix this `preseed.cfg` or manifest with an older payload.
These source changes affect newly installed hosts; replacing the served tree
does not automatically rewrite existing users' home-directory Waybar configs
or reload policies on already-installed machines.

On a disposable target, exercise repeated switcher open/select/Escape cycles
and verify other Waybar modules remain clickable and the transient service
exits. Check both icon buttons on internal and external outputs. With the real
Moo and GRUB packages installed, validate both generated menus, create/delete a
Timeshift snapshot, check completion and timer refresh, and test the intended
snapshot boot/restore path. Finally run firstboot with the intended AppArmor
mode and inspect the audit log for the reported directory denial and any new
one. Keep a known-good boot entry and an independent backup for boot testing.
