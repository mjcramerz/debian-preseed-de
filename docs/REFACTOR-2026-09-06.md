# Debian unattended desktop refactor - 2026-09-06

> Historical report for the preceding security/browser revision. Its test counts
> and credential-mode description have been superseded by
> [the initrd credentials repair](INITRD-CREDENTIAL-FIX-2026-09-06.md).
> Current run evidence is in `validation/summary.json` and `docs/VALIDATION.md`.

## Status and scope

The delivered tree corrects the reported CUDA repository-fetch failure, removes
APT authentication bypasses in the legacy CUDA path, redesigns the browser policy
and import deployment, and adds 39 regression tests to the retained 232-test suite.
The completed five-stage validation pipeline passed all 271 tests with zero skips.
This is source/fixture validation, not a completed real Debian installation.

All 13 supplied hardware profile files retain their original bytes. Account,
network, disk selection, desktop integrations, package selections and the large
Labwc/wlroots application set are not replaced by a generic template. The source
layout remains compatible with existing class/profile selections. Specific
security-sensitive changes and remaining limits are documented below.

## 1. The fatal CUDA lookup

### Observed code defect

`installer_fetch_url` used the same source-fetch function as repository members.
Once `payload.ready` exists, that function correctly refuses a file absent from
the validated snapshot. NVIDIA's external `3bf863cc.pub` was therefore looked up
as though it were part of the pinned installer archive. That produced the user's
`file absent from validated payload` error. Adding an unvalidated fallback to the
snapshot fetcher would hide the symptom while breaking its trust boundary.

### Correction

`scripts/common/source.sh` now supplies `source_fetch_external` for HTTPS data;
`scripts/common/lib.sh` routes the external URL helper through it. The fetch uses
private temporaries, atomic publication, safe relative names, bounded retry/error
behavior, non-executable modes and mandatory TLS verification. It does not inherit
the optional repository TLS bypass. The original snapshot fetcher still rejects
missing or altered members. A real loopback HTTPS regression exercises the
reported ready-marker scenario.

### APT authentication and legacy certificate

Three old source-line generators bypassed authentication with `trusted=yes`,
`allow-insecure=yes` and/or `allow-weak=yes`. The replacement centralizes the
approved Debian 12 CUDA URL, key path and full NVIDIA fingerprint:

    EB693B3035CD5710E231E123A4B469963BF863CC

APT receives both a dedicated Signed-By keyring and that fingerprint. Wrong keys
and altered metadata are not accepted. Public-key ASCII armor checks reject HTML,
empty and oversized downloads before publication; they are not represented as
cryptographic verification. NVIDIA publishes the fingerprint in its signing-key
reference [1]. The key remains an external HTTPS installation-time download.

A second failure is possible on newer Debian APT: this older certificate uses a
SHA-1 binding/self-certification signature, as recorded in NVIDIA's issue tracker
[2]. The code tries strict verification first. Only the exact fingerprint plus the
specific SHA1 binding/PositiveCertification diagnostic permits a single-source
retry. A temporary copy of APT's Sequoia baseline extends only SHA-1
second-preimage acceptance to **2027-02-01**, while SHA-1 data/Release signatures
remain rejected. Every other baseline rule is retained. The baseline is never
modified globally. APT's supported per-process crypto-policy environment is used
[3,4]. Unrecognized policy input, TLS errors, a wrong key and unrelated failures
do not trigger this exception.

This is a bounded compatibility compromise, not stronger-than-default cryptography.
Use a corrected upstream certificate when available, and review the code before
2027-02-01; do not blindly move the cutoff. The existing legacy package family was
not switched to a newer repository without proving equivalent package coverage.

The early apt-setup generator now defers this temporary source to pre-pkgsel,
where it can be updated in isolation. General metadata refresh temporarily hides
only this source and restores it through exit/signal cleanup. The temporary source
and key are removed after legacy repair. Calls to `run_in_target` that may exit
are isolated so failure handling and cleanup actually run.

## 2. Other installer/runtime corrections

The NVIDIA DKMS diversion now uses `dpkg-divert --rename --add`, preserving the
real executable. The wrapper no longer falls back to its own pathname when
`dkms.distrib` is absent; it exits 127 with a diagnostic instead of recursing.
Signal handlers for the two affected pre-pkgsel hooks now exit with signal-related
statuses and finalize logs through the exit trap.

Both private environment-file readers check regular-file/symlink, ownership and
0400/0600 permission requirements before sourcing shell content. In d-i this
means root ownership. Supplying an insecure file fails instead of executing it.
The file remains trusted shell configuration, not an untrusted-data parser.

Builder writes use unpredictable temporary files, fsync and atomic replacement.
Browser generation is part of the ordinary build and check workflow, so policy
edits, export inputs and payload pins cannot silently diverge. Existing immutable
snapshot semantics, safe archive handling and all profile values are retained.

## 3. Browser policies

Four managed-policy locations are covered: Vivaldi, Chromium, Microsoft Edge and
Google Chrome. All receive DeveloperToolsAvailability=1,
RemoteDebuggingAllowed=true and ExtensionDeveloperModeSettings=0. These allow the
DevTools and extension-development functions relevant to the reported denial;
0 is the allowing value for the extension-developer-mode enum [5,6]. Restart the
browser and inspect its policy page; another management source may override local
files. Do not delete unrelated corporate policies as a workaround.

Vivaldi's NoScript, uBOL and Privacy Badger entries use `normal_installed`, not
forced install/removal, so the user can disable/remove them and edit extension
settings. No dashboard/filter-mode/picker/developer UI locks remain. uBOL's only
managed extension setting suppresses its first-run page; the user's imported
rulesets and modes remain editable. Upstream documents dashboard and filtering
locks explicitly [7]. Privacy Badger's two no-DNT settings remain enforced in
accordance with the requested no-signal configuration. Other supported browsers
receive the policy/debug helpers but do not automatically install these extensions.

Unverified, obsolete or speculative policy knobs were removed rather than filling
files with ineffective settings. Verified recommendable privacy/usability settings
are placed under `recommended`. Content-setting defaults that do not support
recommendation are seeded as ordinary fresh-profile preferences instead, so the
user can change them. Notifications, sensors and popups default to blocked;
other sensitive hardware/location/clipboard/file access keeps browser prompting.
TLS validation, sandboxing and download/malware protection are not disabled.
Chrome-only Safe Browsing settings are not copied into Edge.

### Developer debugging helper

    browser-devtools vivaldi --port 9222
    browser-devtools chromium --port 9223
    browser-devtools edge --port 9224
    browser-devtools chrome --port 9225

Run as the ordinary desktop user, never sudo. The helper uses a separate private
profile under `~/.local/state/browser-devtools/<browser>/`, checks unsafe ancestry,
uses only known system browser binaries and loopback, and does not disable the
sandbox. It starts no persistent service and opens no firewall port. Chrome 136+
requires a non-default data directory for normal remote-debugging switches [8].
An unauthenticated debugging endpoint controls the debug profile; close the browser
when done and use a trusted SSH tunnel rather than a public listener.

Existing AppArmor local includes now permit only each browser's dedicated debug
state. Vivaldi's parent and bwrap child receive the appropriate paths. Both actual
Vivaldi parent profiles compile offline with no kernel load. Chromium/Edge includes
are regression-checked, not live-enforcement certified. Chrome had no corresponding
custom local profile in the supplied tree. No browser was launched under changed
host policies in this validation environment.

### The two other Vivaldi log entries

The SVG decode error and missing-extension promise rejection are separate from
remote-debugging policy. The old forced removal of Proton VPN's extension ID was
removed. An existing profile can still contain a stale panel/shortcut reference;
remove that reference in the UI or deliberately reinstall the desired extension.
The SVG decoder is browser code, not an enterprise policy. The import guide gives
a non-destructive cache backup/rename procedure with Vivaldi stopped. A persistent
decoder problem still needs upstream investigation; this repository does not
claim to patch it.

## 4. Bookmark and extension configuration

The normalized input preserves URL, title and ancestor folders, while excluding
embedded icon blobs and avoiding a second copy of the original Privacy Badger
tracking history. Original input hashes and export versions are in
`browser-config/provenance.json`.

| Accounting | Entries |
| --- | ---: |
| All bookmarks | 691 |
| Eligible HTTP(S) bookmarks | 543 |
| Distinct eligible origins | 338 |
| Entertainment/Imported descendants excluded from grants | 100 |
| Browser-native/non-web entries | 48 |
| Live-tested site workflows | 0 |

The excluded folders are recursive; a host also bookmarked elsewhere can still
receive a grant from the eligible occurrence. Exclusion is not a bypass of the
global blockers. `bookmark-coverage.json` gives a row for every entry, including
reason/status and the explicit lack of live verification. All eligible entries
are covered by NoScript mappings and the global uBOL/PB posture; they are not
all globally allowlisted.

**NoScript:** the 338 first-party origins receive contextual app-capability grants
only for their own top-level contexts. Generic Google/Microsoft/CDN TRUSTED grants
are removed. The generated configuration includes 131 scoped dependency candidates
and 29 reviewed tracker blocks. Object, ping, LAN and unchecked-CSS capabilities
are not broadly granted; media/WebGL/Wasm are limited to selected use cases.
The original instance UUID is removed. This uses the inspected NoScript policy
and import model [9,10], but dependencies are hypotheses, not captured network
traces. These are practical starting permissions, not measured minimums.

**uBlock Origin Lite:** the six upstream defaults are retained: uBlock filters,
EasyList, EasyPrivacy, Peter Lowe's list, uBlock badware, and URLhaus. The imported
delta adds URL tracking removal, Block LAN, Swedish filters, cookie notices and
notification annoyances. The global mode is Optimal, not Complete, to balance
filtering against work-app compatibility and generic cosmetic-filter cost.
Complete and list changes remain available to the user. The old GitHub bypass and
browser-internal/extension-ID hostname entries are removed. Strict block mode is
on; experimental popup blocking is off. Enabling every regional/aggressive list
is deliberately avoided. Confirm the installed extension still recognizes the IDs.

**Privacy Badger:** current upstream pre-training is retained; local learning and
incognito learning are disabled. The new import contains 29 reviewed explicit
tracker-block actions, no invented snitch observations and no copied browsing or
fingerprinting history. Bookmarked sites are not added to global third-party
allowlists. Import MERGES existing state [11]: empty exception arrays do not clear
old exceptions. Back up first, use a fresh/reset extension state for reproducible
results, and inspect Disabled Sites and overrides after importing.

`sendDNTSignal=false` and `checkForDNTPolicy=false` are set in both PB export and
managed settings. Upstream's first setting controls BOTH DNT and GPC [12], so both
signals are disabled. Chromium-family fresh-profile DNT preferences are false;
Edge additionally has the supported ConfigureDoNotTrack policy. No fabricated
Chrome EnableDoNotTrack enterprise policy is used. Disabling signals alone does
not prevent fingerprinting.

No static HTML bookmark export can reveal every authenticated login/CDN/CAPTCHA,
media or payment dependency. In particular, local-router administration may need
a narrow LAN/TLS adjustment; neither TLS verification nor Block LAN is globally
disabled here. Website acceptance remains mandatory for the user's actual tasks.

## 5. Target deployment and safe import

The installer stages these five files in the selected account's Downloads:

    noscript_data.txt
    my-ubol-settings.json
    PrivacyBadger_user_data-9_6_2026_1_50_43_PM.json
    bookmark-coverage.json
    BROWSER-IMPORTS.md

`install-browser-imports` runs inside the target as root, resolves the account
through its password database, validates source/directory/file ownership and
symlink safety, and publishes user-owned mode-0600 files atomically. Re-running
preserves edited files and uses a non-clobbering `.install-update` path for changed
payloads. Sources are kept in root-private `/usr/local/share/browser-imports/`.
There is intentionally no automatic extension-database importer: each extension's
own supported UI is the import boundary. Debug and ordinary profiles are separate.

The existing desktop prerequisites still apply, including account/GPG/Fruux/
Telegram credentials and deployment-specific network/disk selection. Put secrets
in trusted root-private `/preseed.env`, not the tarball or URL. Missing late-stage
integration settings can still fail a late installation stage. Consult README and
SECURITY before booting any destructive unattended profile.

## 6. Reproduce and release safely

    python3 -B tools/build.py --check
    python3 -B tools/validate.py

After edits use `tools/build.py` without --check, then validate. Publish the whole
built tree atomically, including preseed.cfg, payload.manifest and payload.tar.gz.
Keep the personalized server private. Pinning inside the preseed does not
authenticate a hostile initial preseed; use trusted media or correctly validated
HTTPS and restrict installation clients. Review selected disks before boot.

Detailed logs and honest blocked/untested outcomes are in `validation/` and
`docs/VALIDATION.md`. The audit has 154 dependency-blocked Perl checks, 116
structural-only systemd checks and two unrendered templates. No real d-i boot,
NVIDIA build/module load, graphical login, Secure Boot or live bookmark workflow
was performed. Do not interpret the 271 passing fixtures as proof of those tasks.
