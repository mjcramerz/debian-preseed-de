# Installer software download timeout correction — 2026-10-23

## Report and source trace

The reported curl error was `operation timed out after 3000000 milliseconds with
114127534 out of 137994129 bytes received`, after Tor Browser installation.
That is 3,000 seconds (50 minutes), with approximately 83% received. The report
does not identify the URL or application. The current source does not contain
a 3,000-second curl timer in this stage, so that exact timer/artifact is not
attributed to a particular application or source revision.

`scripts/late/software.sh.tmpl` installs Tor Browser, optionally bootstraps
ChatGPT/Codex when the DevOps class is selected, then downloads Bitwarden and
the other managed applications. Its shell downloader specified curl
`--max-time 300`. The Perl `APTRepoLocal::Servicing::HTTP` downloader used by
ChatGPT/Codex, Discord and other servicing adapters had a 300-second request
limit and a 1,200-second total operation deadline. These could abort downloads
that were still receiving data. No outer elapsed-time limit was found in
`run_in_target` for the ChatGPT bootstrap call.

`scripts/late/core.sh` stages `runtime/Managed/Process.pm` in
`install_target_firstboot_logger`, called by both storage-family late runners
before `dispatch.sh` invokes selected application helpers. The software helper
then stages `Servicing/HTTP.pm` before invoking its bootstrap consumer. Both
modules therefore come from the same pinned payload. The existing updater
AppArmor profile already permits reading the runtime module and its private
work files; no policy expansion is required for the size observations.

## Changes

- `d-i/forky/scripts/late/software.sh.tmpl`: remove the fixed transfer duration,
  detect a stall below one byte per second for 300 seconds, keep three retries,
  disable implicit curl configuration, and identify the application before
  downloading without exposing redirect URLs.
- `d-i/forky/hooks/target/usr/local/lib/perl5/site_perl/apt-repo-local/APTRepoLocal/Servicing/HTTP.pm`:
  remove request and total elapsed-time caps, use the same curl stall detection,
  and supervise the private partial file with a renewable inactivity deadline.
  The 1,500-second inactivity window accommodates curl's four attempts and
  normal retry delays. It renews when file identity or size changes, including
  truncation when curl starts a retry. Curl failures report the application and
  exit code or signal; captured URLs and response data remain private.
- `d-i/forky/hooks/target/usr/local/lib/perl5/site_perl/runtime/Managed/Process.pm`:
  add an optional bounded progress-marker callback. Only callers supplying it
  renew their deadline. Existing total deadlines, raw wait status, interruption,
  capture bounds and bounded child cleanup are preserved in source.
- `d-i/forky/tests/test_process_capture.py`: add an unexecuted fixture for a
  transfer lasting longer than its inactivity window, an ordinary total
  deadline, and a stalled file despite continuing diagnostic output.

Active transfers in these two download paths no longer have an elapsed-time
cutoff. Disconnected or stalled transfers can still fail after retries. Curl's
existing retry behavior restarts failed partial transfers; this change does
not add byte-range resumption. HTTPS, allowed hosts, size bounds and subsequent
package/hash/signature validation remain in place.

Other installer and runtime downloaders have their own policies. This correction
covers Tor Browser and the shared managed-software bootstrap/servicing paths
described above; it does not remove unrelated network deadlines throughout the
repository. The root JSON inventories are not regenerated by `make build` and
remain stale relative to the new payload.
