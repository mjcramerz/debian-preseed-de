# Debian preseed desktop: targeted implementation and evidence review

Review identifier: 2026-09-21. Target requested: Debian Forky, systemd 261.2,
Waybar 0.15.0. Log timestamps are retained as recorded; several records cross
midnight into September 22. This is the complete repository, not a patch-only
release. Existing host profiles, provisioning logic and historical review files
are retained.

## Release status

The requested Waybar styling, native-menu icon structure, wlsunset startup
correction, evidence-specific AppArmor permissions, time synchronization and
bounded application startup are implemented. The WPA service has targeted
hardening that retains its physical-radio and certificate access requirements.
The installer now invokes the native-menu integration validator, rather than
only the drawer-icon validator.

**This is not a claim that every supplied failure has been eliminated.** The
GTK accelerator assertion has an upstream Waybar tray fix, but the published
Forky package examined for this review remains 0.15.0-1. No source rebuild,
upstream patch, injected library, tray removal or stderr suppression is included.
DRM atomic-commit and USB-C firmware errors need hardware testing. An expired
certificate and security-scan alert lack the detailed evidence needed for a safe
repair. These are explicit acceptance blockers, not findings marked fixed.

No changes were made to the existing private-Xwayland implementation for Zoom
and Discord. No global Xwayland was enabled. The Waybar action mappings and
private-Xwayland-related files are byte-compared with the uploaded archive in
`validation/review-20260921/source-change-inventory.json`.

## 1. Waybar controls and application drawer

The changes are confined to `d-i/forky/hooks/target/etc/skel-desktop/.config/waybar/style.css.tmpl`.
The main-menu control now has a dark-navy normal background and amber text; its
warm amber-brown hover and amber border remain distinct. Workspace controls use
navy at rest, a lighter navy with a faint amber outline/glow on inactive hover,
and the amber-to-soft-orange gradient for the active workspace, including its
hover state. The existing urgent state is not overwritten.

The five application-drawer items use a dark violet/slate hover with a soft
purple outline. Their icon images are still declared once in the normal rule.
Hover changes `background-color`, not the `background` shorthand, so hovering
does not reset the icon image. Existing actions, order, launchers and application
paths are unchanged. Tests reject a reintroduced shorthand image reset.

## 2. Native GTK3 menus

The power, audio, calendar, notifications and Tomat XML files now consistently
use the requested structure. Across 11 menus and 48 menu items, every menu has
`reserve-toggle-size=False`; each item has a visible horizontal `GtkBox` with
spacing 8, one symbolic `GtkImage`, and one left-aligned expanding `GtkLabel`.
Every image has `visible=True`, `pixel-size=18`, `width-request=20` and
`use-fallback=True`. GTK3 explicitly supports icon-name fallback [1]. Existing
symbolic names, item IDs, submenu structure, leaf actions and labels are retained.
No accelerator-group object is misleadingly added to this XML.

The menu palette is implemented as requested:

| Element | Value |
|---|---|
| Background / border | `rgba(8,17,31,0.985)` / `rgba(236,184,96,0.34)` |
| Normal label / icon | `#f5efe3` / `#dfe6ef` |
| Submenu arrows | `#ecb860` |
| Hover background / inset outline | `rgba(236,184,96,0.16)` / `rgba(236,184,96,0.42)` |
| Hover label / icon / arrow | `#fff7e9` / `#ecb860` / `#ecb860` |
| Disabled label and icon | `#7f8999` |
| Separator / shadow | `rgba(174,183,198,0.18)` / `rgba(0,0,0,0.36)` |

Menu labels explicitly use weight 400, not bold. Both pointer-prelight and
keyboard-selected states are styled; disabled items retain their disabled
colors. The installed validator checks geometry, symbolic names, ownership,
unique IDs, leaf-to-action equality, subprocess options and helper integration.
A validator failure aborts the desktop provisioning flow before the subsequent
Codex step; it is not ignored.

Native GTK3 tests use the system GTK shared library in a disposable Xvfb display,
not a substitute XML parser alone. They exercise ten rendered host profiles,
both bar layouts, Adwaita and Adwaita-dark, and Whisper available/unavailable
branches. The matrix includes 400 menu roots, 3,200 leaf activations and more than
10,000 highlight-state checks. It also checks icon geometry, disabled states,
font weight, submenu behavior and notification-center reachability. Control
commands are intercepted; tests do not reboot, suspend, record audio or change
the host's session. `G_DEBUG=fatal-criticals` is enabled in the GTK fixture.
Papirus itself and the target Wayland compositor are not installed in this test
environment; final theme rendering on the target remains an acceptance check.

### Separate GTK accelerator defect

Waybar upstream PR 5164, merged July 4, 2026, identifies the tray's missing
`GtkAccelGroup` on its `DbusmenuGtkClient`. When a tray application exports
accelerators, that path passes a null group into GTK and produces the reported
critical assertion. The upstream correction is commit `fae2b31` [2]. That object
is separate from the five custom GtkBuilder menus; changing their image or label
properties cannot initialize it.

The Forky package page still lists Waybar 0.15.0-1 [3]. The retained package path
therefore does not establish that the fix is installed. Acceptance requires a
trusted distribution binary containing that correction and a tray-menu retest.
No unsupported package version is pinned or silently fetched, and no source
compilation is introduced. The tray remains available. This defect is not
reported as resolved by the successful custom-menu tests.

## 3. wlsunset and process ownership

The wlsunset log contains three failed execution attempts with
`218/CAPABILITIES`, followed by the restart limit. These failures precede execution
of wlsunset; they do not demonstrate a gamma-control or DRM failure. systemd's
execution documentation identifies that status with capability setup [4].

`usr/local/bin/labwc-wlsunset` no longer requests `CapabilityBoundingSet=` or
`AmbientCapabilities=` from this unprivileged user service. No capability is
granted to the user manager as a workaround. `NoNewPrivileges=yes`, AppArmor,
seccomp, AF_UNIX-only networking, namespace restrictions, environment filtering,
resource limits and secure root-owned configuration checks remain. The service
still binds to the compositor and session, has a 10-second startup deadline,
5-second stop deadline, cgroup termination, and bounded restart policy: at most
three attempts within 300 seconds, with a 10-second restart interval.

The generic managed-application launcher now also sets `TimeoutStartSec=10s`.
It retains `ExitType=cgroup`, session prerequisites and teardown binding,
`--collect`, a 20-second stop deadline, final SIGKILL behavior, restrictive umask
and the closing-session guard. The existing terminal-specific mixed kill policy
and application-specific privilege exceptions are preserved. No global runtime
limit is imposed on intentionally long-running desktop applications. Existing
native menu actions already use bounded, nonblocking transient user services;
the newly wired validator verifies those options.

These changes preserve the established ownership design instead of introducing
a second supervisor, extra polling loop, or broad process-name killing. They do
not prove that all third-party processes exit correctly under every workload.
Two logged `foot -e btop` exit-status-1 cases followed terminal child hangups.
Their explicit-command failures are not reclassified as successful exits; the
existing success exception remains restricted to the default interactive shell.

## 4. Network and Lynis findings

`network-log-disposition.json` records the relevant journal line references.
The log shows NetworkManager reaching `CONNECTED_GLOBAL`. Nineteen idle scan-MAC
rotations and adjacent station/P2P management state changes do not demonstrate
an established Wi-Fi connection dropping. Scan privacy is retained. The
unmanaged-P2P policy prevents activation; it is not advertised as removing
hardware discovery. The supplicant's `-c` file is not assumed to override all
interfaces that NetworkManager creates through D-Bus.

Tailscale startup health warnings subsequently clear, with the tunnel entering
its running state. The netavark helper explicitly exits after 30 seconds of
inactivity. Neither is repaired by resetting credentials, disabling DNS checks,
or adding perpetual restart loops. The journal's escaped ifup unit name is not
an interface-renaming defect.

### Targeted changes

The existing WPA system-service drop-in retains its ExecStart and host radio
access. It now restricts capabilities to `CAP_CHOWN`, `CAP_DAC_READ_SEARCH`,
`CAP_NET_ADMIN` and `CAP_NET_RAW`; clears ambient capabilities; enables
NoNewPrivileges; makes the system and homes read-only as appropriate; isolates
temporary files; protects kernel tunables/modules/logs and control groups;
restricts address families and namespace creation; disables core dumps; and
uses a private umask with bounded cgroup shutdown.

The netdev control-socket group needs ownership-changing permission. Read/search
DAC bypass is retained for EAP certificate/key files in private directories,
without retaining the broader write-bypass capability. Linux distinguishes
these capabilities [5], and NetworkManager supports file-based EAP certificate
configuration [6]. AF_UNIX, AF_NETLINK, AF_PACKET, AF_INET and AF_INET6 remain.
No `PrivateNetwork` or `PrivateDevices` restriction hides the physical adapter,
EAPOL or rfkill. Actual Wi-Fi/EAP authentication must still be exercised on the
target; an improved Lynis numeric score is not claimed.

The desktop package selection now includes `systemd-timesyncd`, and the existing
service-enabling stage enables it. This addresses the missing time-sync client
reported by Lynis using the distribution's packaged implementation [7]. Existing
NTP firewall policy is preserved. No extra daemon, untrusted time server or
blocking boot-time synchronization loop is added.

### Findings not safely closed by a configuration rewrite

The journal records an administrator explicitly stopping `nftables.service` at
September 22, 01:26:40. This is not an unexplained service crash. The captured
firewall log contains 44 allow records, not denial evidence explaining a
connection failure. The desired managed firewall must be restored and verified
before acceptance; this code does not override a deliberate administrative stop
with an automatic restart policy.

All 31 explicit Lynis UNSAFE unit ratings and 32 recommendation lines have
individual dispositions in `lynis-disposition.json`. systemd exposure ratings
measure use of service hardening mechanisms, not complete application security
or proof of exploitation [8]. Login, audit, storage, VPN and container services
are therefore not indiscriminately given desktop-app restrictions.

Lynis reports one expired certificate among 276 without its path, issuer or
purpose. Detailed scan output is needed; deleting trust anchors or disabling TLS
verification would be unsafe. The root-context Docker check does not establish
failure of the configured rootless user workload; its detailed error must be
checked as the owning user, without exposing the socket globally or installing
a competing rootful daemon. A chkrootkit alert has no detailed findings in the
supplied empty scan file and is not dismissed as a false positive.

The journal shows sysstat collection despite the scanner's disabled
classification. Existing source already sets `fs.protected_fifos=2` and reverse
path filtering to 1; a runtime DIFFERENT finding requires inspecting the loaded
settings and routes, not guessing a new sysctl value. Recovery SysRq, hardware
hotplug, supported removable storage and developer compiler access are retained.
A long cryptographic audit test is not itself a network throughput bottleneck.
No blanket chmod, account change, partition redesign, duplicate scanner or
credential reset is included merely to improve audit scores.

## 5. AppArmor and kernel audit coverage

The review inventories all 46 supplied log files: 41 files from managed.zip plus
the five loose logs, totaling 23,596 lines. Twenty-seven files are empty; they
are recorded as containing no evidence, not proof that their subsystem is
healthy. All AppArmor records were classified, including the kernel-audit files.
Repeated transport copies were deduplicated by audit timestamp/serial within
each semantic group.

The 3,034 complain-mode ALLOWED records with denied permissions represent 1,517
unique events and only five missing-permission patterns. The 800 STATUS records
are profile loading/mode information. There are 404 semantic groups in total:
five complain patterns and 399 status groups. Four kernel-command-line mentions
of `apparmor=1` are not miscounted as policy events.

| Profile / operation | Transport records | Unique events | Narrow change |
|---|---:|---:|---|
| managed-waybar / directory read | 2,592 | 1,296 | `r` on `/usr/local/lib/python3.14/dist-packages/` itself |
| managed-desktop-launcher / ptrace read of managed-labwc-swaybg | 146 | 73 | Named-peer `ptrace (read)` |
| managed-desktop-launcher / ptrace read of managed-tomat | 292 | 146 | Named-peer `ptrace (read)` |
| managed-desktop-launcher / ptrace read of managed-labwc-notifications | 2 | 1 | Named-peer `ptrace (read)` |
| managed-zram-device-setup / PSI read | 2 | 1 | `r` on `/proc/pressure/io` |

These are five additional permissions in three policy files. No recursive
Python-tree write rule, arbitrary-peer ptrace permission, attach/trace grant,
capability expansion, audit suppression or bulk complain/enforce-mode conversion
is introduced. The named peers' existing reciprocal read-by permissions were
checked. Complain mode allowing an operation is not mistaken for a correctly
specified enforcement policy.

All 81 repository policy/include files are inventoried. All 37 top-level policy
files passed offline AppArmor parser checks with the repository includes overlaid
on the environment's distribution abstractions. This verifies parseability, not
runtime enforcement on Forky; no policy was loaded into the running kernel.
Profiles without observed denials are not declared exhaustively validated for
unexercised workloads.

Kernel audit also contains 76 `unlinkat` ENOENT results from idempotent cleanup
of already absent files and five systemd `rmdir` ENOTEMPTY results. These are not
AppArmor access denials. The implementation does not delete nonempty directories
or add permissions to hide these syscall results. Related PATH, CWD and
PROCTITLE records are counted without being presented as extra failed calls.

## 6. Other failures and residual acceptance items

The DRM excerpts contain two distinct eDP-1 atomic-commit EBUSY timestamps,
September 21 at 23:49:15 and September 22 at 00:00:05, with duplicated copies.
USB-C logs also contain UCSI error 88 / GET_PDOS -5 failures. The supplied logs do
not establish a safe installer-level correction. No atomic modesetting,
PSR/VRR, USB driver, output or power-management feature is disabled speculatively.
Reproduction with the actual GPU, firmware, kernel, displays and dock is needed.

The absent global Xwayland executable is consistent with the requested private
architecture and is not repaired by exposing global X11. Crystal Dock's
LayerShellQt deprecation and Tuta's Node/packaging warnings are retained as
vendor diagnostics; their sources are not patched. Fuzzel cancellation, zram
pressure below threshold, successful Timeshift GRUB refresh and an unsuccessful
sudo authentication followed by success do not justify changing access policy.
The existing repeated Waybar power-message coalescer is unchanged and retains
the first diagnostic.

## Validation and reproducibility

The final orchestration results are in
`validation/review-20260921/final/summary.json`; individual command output is in
the adjacent logs. A concise generated validation result is also stored at
`validation/review-20260921/validation-summary.json`.

Final clean run: **2,272 main-suite tests, 49 recorded skips, zero failures or errors**; **179 tools-suite tests, 0 skips, zero failures or errors**. All seven validation stages completed successfully. Skipped tests are not counted as executed passes.

The payload was regenerated from the changed source: `payload.tar.gz`,
`payload.manifest` and `preseed.cfg` are aligned. The payload contains 1,403
files. Browser configuration, generated-build consistency, preseed checks and
shell syntax checks are part of the final validation. Shell checking covers
282 files and 575 parser checks, not every possible shell runtime behavior.

The first broad run exposed two stale test expectations after the orchestration
call changed, plus a 40-second staging-fixture timeout. The two expectations
were updated to the new native-menu validation call; historical resource-policy
hashes were not rebaselined. A new test verifies that menu validation failure
propagates. The resource-policy module passed independently on rerun. Initial
logs remain present for transparency; final results supersede them.

The broader code audit inventories 1,331 files: 471 pass, 180 structural pass,
158 dependency-blocked, 11 tool-blocked, 509 inventory-only and 2 templates
requiring rendering. It is not represented as 1,331 executed tests. Missing
Perl Moo/MooX dependencies and unavailable tools are recorded rather than

Validation ran in Debian 13.3 with systemd 257.9 and AppArmor parser 4.1.0, not
a booted Forky/systemd-261.2 target. The WPA drop-in passed unit syntax checking
against an inert synthetic unit with `/usr/bin/true` substituted because the
actual WPA executable is absent here; that is not a radio authentication test.
No live target install, compositor, GPU, user-manager teardown, enforcement-mode

`source-change-inventory.json` records all 4,015 original files as present,

## Deployment and target acceptance

Serve the entire extracted repository as with the existing installation workflow,
not just the changed templates. Use the regenerated payload and preseed together.
Do not run unattended disk-installation scripts directly on an existing working
host. Skeleton configuration changes do not automatically replace files in an
already installed user's home.

After a controlled target installation, collect a new boot's evidence rather
than treating historical warnings as a post-change result. Inspect:

```sh
systemctl --user status labwc-wlsunset.service
systemctl --user show labwc-wlsunset.service -p Result -p NRestarts -p KillMode -p TimeoutStartUSec -p TimeoutStopUSec
journalctl --user -b -u labwc-wlsunset.service
systemctl is-active NetworkManager wpa_supplicant systemd-resolved systemd-timesyncd
nmcli device status
resolvectl status
timedatectl show -p NTPSynchronized
systemctl is-active nftables
sudo nft list ruleset
sudo aa-status
sudo journalctl -k -b --grep='apparmor='
```

The desired results are an executing wlsunset without capability setup failure,
working expected network interfaces and DNS, actual time synchronization, the
managed firewall active with its intended rules, and no new unexplained denial
patterns. Exercise actual EAP profiles with private certificate paths, Wi-Fi
reconnect, VPN/container networking, suspend/resume and display hotplug. Test
menu pointer/keyboard/disabled states and application actions on both bar
layouts. Close applications and log out while checking for session-owned
leftovers; verify that only Zoom and Discord receive their private Xwayland.
Retest tray menus after obtaining a trusted binary containing the upstream fix.
Resolve the certificate/scan findings from their detailed reports and reproduce
the DRM/UCSI errors before declaring all requested objectives fully accepted.
