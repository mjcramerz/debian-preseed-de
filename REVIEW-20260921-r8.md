## Root cause and reproduction

Debian's FreshClam post-installation script assigns the generated configuration to
its database account, normally `clamav`, with group `adm`. It uses mode `0444`, or
`0400` for proxy credentials. This packaging contract was verified against Debian's
published 1.4.6+dfsg-1 source for Forky/Sid. [S1]

The previous managed helper incorrectly required `freshclam.conf` to have UID 0.
It therefore raised the reported error on an ordinary package-generated file:

```text
session-repairs: unsafe freshclam configuration
```

The failure occurs before the helper decides whether `NotifyClamd` needs changing.
Consequently the existing `NotifyClamd=false` preseed does not prevent this failure:
a valid configuration without any notification directive is rejected too.

Before modifying the helper, the error was reproduced in all four combinations of
0444/0400 and a present/absent stale default notification. Real temporary-file
ownership was changed to a nonzero UID with group 4; no host configuration was
modified. Evidence is in `validation/freshclam-r8/baseline-reproduction.json`.

The older scanner-only tests created root-owned files. They covered symlink and
mode handling but missed Debian's package-owned configuration. The new tests
exercise actual nonzero UID ownership, including real target-style passwd/group
lookups in a child chroot. They deliberately use a fixture UID rather than assume
Debian assigns a fixed numeric UID.

The failed target's file metadata and installed package version were not provided.
This establishes and fixes a reproducible repository defect matching the reported
message; it is not a claim to have inspected that machine's filesystem.

## Narrow repair and retained safeguards

The FreshClam data-file check now accepts root or the UID resolved for the named
`clamav` account inside the target. It does not trust a UID merely because it is a
system user, shares a group, or is named by `DatabaseOwner` inside the file. A
missing package account does not authorize a non-root owner. Root-owned
administrator configurations remain supported without requiring that lookup.

This exception applies only to `freshclam.conf`. The configuration directory and
any present `clamd.conf` retain their root-ownership and non-writable-group/other
checks. Debian's separate daemon post-installation script uses root:root for
`clamd.conf`; its existing check was not relaxed. [S2]

For FreshClam, symlinks, hard links, nonregular files, group/other-writable files,
executable files and special permission bits are rejected. Open operations retain
no-follow, close-on-exec and nonblocking flags. The directory is pinned by a file
descriptor; temporary creation is unpredictable and exclusive.

Only the exact default-path notification is commented when the default daemon
configuration is absent. A present trusted daemon configuration or a custom path
is left alone. No credentials, mirror configuration or update scheduling is
rewritten. The existing mandatory `run_in_target` failure propagation is retained.

Reads are bounded to 65,536 bytes, with one extra byte to detect oversize. The
edit operates on bytes rather than decoding and rewriting the whole configuration,
so other bytes, CRLF line endings and a missing final newline are preserved.
Output growth beyond the same bound is rejected before publication, avoiding a
successful edit that would fail its own size check on the next run. This helper
is not a general FreshClam configuration parser or validator.

The replacement retains the original UID, GID and permission mode, including
0400. It is flushed, fsynced and atomically renamed within the pinned directory,
then the directory is fsynced. Failures before publication remove the newly
created temporary file and do not overwrite the original. A pre-existing
colliding temporary name is neither followed nor removed.

Metadata is compared after reading and before replacement. Observed concurrent
source edits or replacement, and a daemon configuration appearing before commit,
abort the edit. These checks are not a claim of general race-free live
reconfiguration against a noncooperating same-UID writer. The helper remains an
offline installer operation. A directory-fsync error after a successful rename
is reported as a failure; no rollback after publication is promised. Extended ACLs
and arbitrary extended attributes are not a newly implemented preservation feature;
the explicit preserved metadata is UID, GID and permission mode.

## Diagnostics

Unsafe-file errors now include numeric ownership, permission mode and link count,
plus the expected policy. They never print the configuration body or proxy secret.
A successful notification repair emits:

```text
session-repairs: disabled stale default NotifyClamd; FreshClam ownership and permissions preserved
```

Both messages use the existing installer command-output logging path. No new log
daemon, service, timer or policy exception is needed.

The child-chroot tests run the complete helper, including its command-line error
handler and following PAM reconciliation, with real `/etc/passwd`, `/etc/group`
and filesystem ownership. After a successful repair, the child drops supplementary
groups, GID and UID to the fixture `clamav` account and verifies that the read-only
configuration remains readable. Repeated invocation is idempotent.

Additional integration cases execute the actual `desktop_stage_session_repairs`
function and actual `run_in_target` wrapper under dash, bash and BusyBox sh. They
verify the staged helper's bytes and 0755 installed mode, successful completion
for valid package metadata, and an actual nonzero exit for unsafe metadata.
Transport/copy, log-routing and hardware commands are fixture boundaries; no real
hardware database rebuild or target installation is performed by these tests.

The focused suite also covers no-op configurations, retained custom/present-daemon
notifications, invalid owners, missing accounts, unsafe modes, symlink and hardlink
inputs, a FIFO with a subprocess timeout, byte limits, failed chown/fsync/rename,
temporary-name collisions, observed edit/replacement races and descriptor cleanup.
