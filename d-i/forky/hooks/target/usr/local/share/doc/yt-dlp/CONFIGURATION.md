# Downloader configuration and plugins

`youtube-dl` opens the terminal menu for YouTube and other sites supported by
yt-dlp. The **Download using saved configuration** action keeps your selected
formats, output paths, filename templates and postprocessors. The explicit
highest-quality video, source-quality audio and playlist actions select their
named mode and ask for an output directory.

The installed `yt-dlp` command also accepts the complete upstream command line.
The menu offers an editor for the recommended user configuration and a file
manager for the user plugin directory.

## Configuration

System defaults are in `/etc/yt-dlp/config`. User settings are in
`~/.config/yt-dlp/config` (or `$XDG_CONFIG_HOME/yt-dlp/config`). Portable,
download-directory, additional `--config-locations` files, alternative user
configuration locations and system configuration keep the upstream discovery
order. The wrappers do not disable configuration or plugin discovery.

Only the selected menu action's explicit command-line options override saved
settings. Use the saved-configuration action or the `yt-dlp` command when you
want full control over those options.

## JavaScript challenges

The official standalone yt-dlp executable contains the matching yt-dlp-ejs
scripts. The system configuration selects the pinned Deno executable at
`/usr/local/lib/deno/bin/deno`. ffmpeg and ffprobe come from Debian under
`/usr/bin`. No additional EJS download is needed for the bundled release.
The runtime and configuration use yt-dlp's normal runtime-selection mechanism.

## Plugin discovery

yt-dlp loads extractor and postprocessor plugin packages from its standard
locations, including:

- `$XDG_CONFIG_HOME/yt-dlp/plugins/<package>/yt_dlp_plugins/`
- `/etc/yt-dlp/plugins/<package>/yt_dlp_plugins/`
- `~/.yt-dlp/plugins/<package>/yt_dlp_plugins/` (legacy user location)
- `/usr/local/lib/yt-dlp/libexec/yt-dlp-plugins/<package>/yt_dlp_plugins/`
- Additional paths supplied with `--plugin-dirs` in your configuration.

Plugin ZIP, wheel and egg archives containing `yt_dlp_plugins/` at their root
also work in these plugin directories. The standalone executable uses these
plugin paths; installing a package into an unrelated system Python environment
does not make its modules available to a bundled Python executable.

The system configuration explicitly includes
`/usr/local/lib/yt-dlp/libexec/yt-dlp-plugins` with `--plugin-dirs`, so the
installer-bundled packages are active for both the menu wrapper and direct
`yt-dlp` use. User supplied plugin directories remain available and are not
replaced by the bundled set.

Extractor plugins are selected automatically for matching URLs.
Postprocessor plugins use their documented `--use-postprocessor NAME` option.

## Supported sites and bundled plugins

The pinned official standalone executable contains yt-dlp's complete built-in
extractor catalog for the pinned release. This includes the normal supported
site extractors such as YouTube, Bilibili, Bandcamp, BBC, Pornhub and the
generic/embed extractors. The upstream `supportedsites.md` list is generated
from the extractor classes; a listed site can still be temporarily broken when
the site changes, so a real URL is the only reliable availability check.

This installation also bundles these checksum-pinned third-party packages:

- `bgutil-pot`: YouTube proof-of-origin provider plugin plus a prebuilt Linux
  provider executable. The system configuration points the plugin at the
  executable in script mode; no background service or container is required.
- `rajiko`: Radiko radio extractor with its bundled `protobug` dependency.
- `apple-developer`: Apple Developer and WWDC session extractor.
- `srt-fix`: optional automatic subtitle cleanup postprocessor.
- `return-youtube-dislike`: optional Return YouTube Dislike metadata
  postprocessor.
- `fixup-mtime`: optional timestamp postprocessor for downloaded files.

Extractor plugins are active automatically. Optional postprocessors remain
opt-in through their documented `--use-postprocessor` options, so a download
does not silently rewrite titles, subtitles or timestamps. The plugin loader
imports installed plugin modules without a safety review; only install plugins
you trust. The user plugin directory and `--plugin-dirs` remain available for
any additional compatible package.

The upstream third-party plugin ecosystem is open-ended, so no fixed installer
can truthfully vendor every package published by every author. This image pins
the useful extractor and postprocessor packages listed above while preserving
all standard yt-dlp discovery locations for additional compatible plugins.

Built-in site extractors, SponsorBlock, subtitle processing, metadata and
thumbnail embedding remain available through normal yt-dlp configuration.

The authoritative built-in catalog is generated by yt-dlp's
`devscripts/make_supportedsites.py` from its extractor classes. The pinned
standalone release carries that complete catalog, including extractors such as
Pornhub and the generic/embed fallbacks; the generated upstream list is
available at
<https://raw.githubusercontent.com/yt-dlp/yt-dlp/43a45ae37419b2a90db710c9fd06cd250ef524d3/supportedsites.md>.

The authoritative upstream references are
[configuration and plugin documentation](https://github.com/yt-dlp/yt-dlp#configuration)
and the [EJS setup guide](https://github.com/yt-dlp/yt-dlp/wiki/EJS).
