## 3. Poweroff and reboot finalization

### Explicit forced-power policy

Both desktop and greeter poweroff/reboot requests now reach the same finalization routine. It submits exactly one of:

```text
/usr/bin/systemctl --force --no-ask-password poweroff
/usr/bin/systemctl --force --no-ask-password reboot
```

There is exactly **one** `--force`; no double-force, `--no-sync`, raw reboot syscall, emergency target, or automatic retry was added.

**This is intentionally not ordinary orderly shutdown.** A single force skips normal shutdown of all units, while PID 1 still performs final process/filesystem teardown. Consequently, unrelated services' normal stop procedures and logind's delay-inhibitor protocol are not guaranteed. The existing document-save, package-lock, account, and managed-guest protections reduce risk but cannot guarantee that every application or background service has persisted its data. Use this policy knowingly.

### Ordered implementation

The existing root worker remains a PID-1-owned system service, outside the desktop/user-manager cgroups. The existing authorization, fixed command environment, serialization, readiness notification, and package-lock reservation remain in place.

For a desktop action, the worker preserves the existing session identity and document-save checks, verifies blocking shutdown inhibitors, quiesces the desktop and its managed units, and finishes the fixed optional guest-stop hooks while their buses are still available. A greeter action has no desktop document-save phase, but uses the same account/package guards, managed-guest hooks, and final cleanup. Suspend and logout retain their existing separate paths.

Immediately before forced power, the worker:

1. Rechecks its package reservation, other interactive accounts, and logind's shutdown inhibitors while the system bus is still alive.
2. Takes a bounded, strictly parsed system-manager snapshot of `greetd.service`, `dbus-broker.service`, `dbus.socket`, and loaded `user@UID.service` instances. Unexpected names, cgroup placements, malformed states, unavailable required broker units, or unreadable cgroup state fail closed.
3. Queues nonblocking, irreversible stop jobs for the selected units. This stops the greeter/login loop and system-bus listener and puts services into the stopping path before signalling them.
4. Asks **PID 1** to send `SIGKILL` to all processes of the system broker and selected user-manager services. User-manager service cgroups include their user brokers and PAM helper processes, so this does not depend on a racy search for a process named `sd-pam`.
5. Verifies inactive/failed unit states, finished jobs, zero main/control PIDs, and removed or recursively empty cgroups. Saved canonical cgroup paths remain checked even when a unit disappears or clears its `ControlGroup` property. A surviving PAM child therefore blocks the forced handoff.
6. Rechecks the package reservation and makes the single forced-power request. Its reservation remains held until PID 1 stops the worker.

After runtime teardown begins, the final phase uses only the root system manager's private IPC path and kernel cgroup reads. It does not request new user services, invoke logind through the departed broker, or require a fresh polkit interaction.

The cleanup targets loaded user-manager services, not arbitrary similarly named processes or the entire `user.slice`. PID 1 may also propagate stop jobs to units that require a selected broker; the worker does not enumerate every system service. The existing account guard is per UID: it is not proof that every other session of the same UID or every lingering background workload has saved state. A newly observed user manager during cleanup aborts the final request; this is a last-moment recheck, not an atomic freeze of every possible login or inhibitor source.

### Failure behavior and bounds

The new inhibitor read has a five-second bus timeout, a seven-second transport deadline, and a one-MiB stdout bound. It accepts the documented `a(ssssuu)` signature and validates record structure, string lengths, and numeric ranges. `block`, `block-weak`, and unknown shutdown-inhibitor modes veto the action. `delay` is not falsely treated as a blocking lock or as an implemented delay handshake.

Cleanup snapshots are limited to 128 units and 128 KiB; stderr is capped at 16 KiB. Stop and signal transports have ten-second deadlines, followed by a ten-second verification window with each query bounded by the remaining time. These are phase bounds, not a promise that every complete power request finishes in ten seconds: document/guest phases retain their own limits, and the existing package-writer wait intentionally has no unsafe timeout fallback.

A signal transport error is tolerated only when independent state/cgroup verification proves cleanup completed. A stop-submission error, unreadable state, remaining job/PID/cgroup population, or newly observed manager prevents the final `--force`. An uncertain final handoff is never automatically retried.

**After destructive cleanup has begun, failure can leave the GUI or D-Bus stopped without powering off.** The worker does not restart user managers or pretend the action was cancelled cleanly. Recovery then requires a prearranged root/VM console and inspection of the worker journal. This fail-closed behavior avoids blindly forcing power after a failed prerequisite.

### Security boundaries preserved

All substantive systemd worker-unit directives are unchanged, including empty `CapabilityBoundingSet` and `AmbientCapabilities`, `NoNewPrivileges=yes`, `ProtectControlGroups=yes`, and the existing system-call filter. PID 1 performs the cross-process signalling. No `pkill`, `pgrep`, `/proc` PID scanning, direct cgroup writes, new `CAP_KILL`, ptrace, or unconfined helper transition was introduced.

Only the worker's profile in `managed-desktop-wrappers` changes: it permits the fixed `busctl` executable under the existing profile and read-only access to the cgroup-v2 controller marker and the narrowly selected `cgroup.events` files. Every other profile in that shared file is byte-identical after removing the worker profile for comparison.

## 5. Reproduction and publishing

From the repository root, the standard validation entry points are:

```sh
python3 -B -m unittest discover -s d-i/forky/tests -p 'test_*.py' -v
python3 -B -m unittest discover -s tools/tests -p 'test_*.py' -v
python3 -B tools/build.py --check
python3 -B tools/check_shells.py
python3 -B tools/check_preseeds.py
```

The new focused modules are `test_power_runtime_20260920.py` and `test_drawer_native_icons_20260920.py`; the GTK button coverage is in `test_notifications_followup_20260920.py`. The private-bus diagnostic can be repeated with `python3 -B validation/followup-20260920-r2/check-private-bus-inhibitors.py .` on a host with the required existing tools. AppArmor parser checks are offline checks, not policy enforcement tests.

`d-i/forky/payload.tar.gz`, `payload.manifest`, and `preseed.cfg` have been regenerated together. Every one of the **1,401 payload entries** was checked against its source and manifest hash. Payload permissions follow the builder's existing 0644/0755 normalization; the outer complete-repository archive preserves original repository permission bits.

Publish the complete repository atomically so new preseed pins never refer to an older payload or manifest. The archive is a complete install source, not a live updater for existing user home directories. Existing installations need deliberate configuration deployment through the established management process; merely replacing the served repository does not alter a running user's Waybar.

## 6. Disposable-target acceptance boundary

This container did **not** boot the user's Debian Forky/systemd 261.2 image. Offline parsing, mocked host transports, real GTK tests, and a private D-Bus contract check do not replace target acceptance with kernel-enforced AppArmor and the actual session manager.

Before production rollout, use a disposable target with an out-of-band VM/root-recovery console available. An already logged-in different UID should correctly trigger the account veto:

- Verify the installed icon-check log, actual vendor artwork, hover retention, and unchanged launch behavior for all five apps in both bar layouts. Check normal/DND notification colors, silver lock, and the power gradient. Recheck all five existing native menus and the Mako center.
- Exercise poweroff and reboot separately from the desktop and from the greeter. Confirm save/guest/package phases precede the journal's cleanup-complete marker and its single-force handoff marker. Use previous-boot journals where persistent logging is available.
- Confirm a genuine APT/dpkg writer keeps the action pending without teardown; a blocking shutdown inhibitor and another interactive UID reject it; save-dialog cancellation does not enter destructive cleanup. Do not remove package lock files to conduct this test.
- Check AppArmor audit logs, canonical cgroup locations, and private PID-1 IPC on the actual systemd build. Test the failure/recovery path in the disposable environment; no second forced command should be submitted automatically. Recheck that suspend/logout and the private Zoom/Discord Xwayland paths remain unchanged.
