## Native IOCost compatibility

Inspected systemd 257/v261 uses `/etc/udev/iocost.conf` rather than a native
`/etc/systemd/iocost.conf.d/` loader. The requested systemd main/drop-in sources
are retained, and the fixed compatibility link points to the sole TargetSolution
directive. Unknown interfaces fail closed. The native reader was checked in an
isolated target fixture, alongside strict hwdb compilation/query and device-match
exclusion tests. No host database or live cgroup was modified.

KXG6AZNV512G values are explicitly provisional, not calibrated or vendor-derived
IOCost measurements. Replace them per host after real resctl-bench calibration.
See `../docs/hardware-tuning/IOCOST.md` for all values and limitations.

## Hardware and runtime limitations

This is source/build and non-destructive simulation validation, not a booted
installer, hardware power-management trial, KXG6 latency test or desktop visual
acceptance. Thunderbolt parameter metadata was available only for an installed
non-running kernel. No actual Intel HWP writes, IOCost application or live
uevents were performed. Remote Microsoft archive bytes were not downloaded;
controlled archive fixtures validate security and two-tree publication.

The complete source archive retains normal generated payload/preseed products
and historical records. File execute/private modes are preserved; archive owner,
timestamps and ordering are deterministic, with safe 0755 directory entries.
