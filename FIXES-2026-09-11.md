# Installed-system failure fixes - 2026-09-11

## Delivery status

This is the complete supplied installer source tree with targeted source changes,
regenerated `d-i/forky/payload.tar.gz`, `payload.manifest`, and `preseed.cfg`, and
new regression tests. It is **not a certification that every reported runtime
failure has disappeared**. The source-level fixes and remaining acceptance gaps
are separated below. No Debian guest was installed or booted in this review.

Xwayland installation, configuration, and launch behavior were not changed.
Labwc was not compiled, and no Labwc source-build path was added. The Xwayland
startup message in Failures2 therefore remains deliberately outside this patch.

## Audit coverage

`tests/fixtures/installed-apparmor-20260911.json` retains the 592 records as 182
unique grouped records, with the home account anonymized. The regression checks
profile scope, observed masks, link targets, owner qualifiers and deleted-entry
handling. Counts are: media 542, Crystal Dock 32, launcher 8, launcher child 6,
glycin 2, and ChatGPT 2. A second regression derives all 182 grouped records
from the supplied raw log and requires an exact count-and-field match, preventing
fixture drift from hiding a new `denied_mask` event.

A successful source-mapping test plus successful parser compilation does **not**
prove that a new runtime denial cannot occur. In particular, complain-mode null
profiles can differ from the intended enforced exec transition. Exercise the
applications under the target kernel before considering enforcement accepted.
Existing profile-mode choices and unrelated explicit deny rules were not removed.

## Remaining failures and uncertainties - not claimed resolved

* `firstboot.service` returns a failure, but its stage output under
  `/var/lib/installer-state/logs/firstboot/` was not part of the supplied archives.
  The audit log confirms a failed stop, not which validation failed. The wrapper
  and its fail-closed checks were deliberately not changed to report success.
  The permissions/portal fixes may remove contributing failures, but that is not
  an established firstboot fix.
* The Waypaper "No enumerators available; falling back to All" message remains
  a vendor limitation in the locally installed pinned stack: Waypaper 2.8 uses
  `screeninfo` for the configured `swaybg` backend, while screeninfo 0.8.1 has no
  Wayland/wlroots enumerator. Avoiding the message would require a different
  wallpaper backend, a third-party source patch, X11, or an unverified version
  bump; none was introduced.
* Bitwarden 2026.8.0 still emitted `sshagent.clearkeys` on an IPC path where its
  vendor handler was not registered. The vendor ASAR contains the legacy handler,
  but changing its registration or forcing an undocumented protocol would rewrite
  vendor code. Network access was unavailable to verify a newer vendor release,
  so no fabricated local Electron handler was added.
* KWallet's i18n, parent-window, QWizard and Wayland text-input diagnostics, and
  the Electron/GTK `gtk_widget_get_scale_factor` assertion, are not proven fixed
  by the policy/order changes. They were not hidden with log filtering.
* `memfd_secret` initialization and `Migrator ... should migrate: false` are
  informational messages in these excerpts, not failed operations.
* The Xwayland startup message is intentionally unchanged under the requested
  constraint. No claim of eliminating every line in Failures2 is made.

## Deploy and accept

The release tar uses root:root archive ownership, 0755 source directories and
executable source files, and 0644 non-executable source files for safe read-only
HTTP publication. Installed private-file modes are still selected explicitly by
the installer; this is not a request to chmod users' home directories. No source
symlinks or special files are published. The original source tree is retained
except for the deliberately removed Bitwarden transformer executable; the
Bitwarden servicing module is retained with its new non-repacking policy role.

Publish the **entire** new repository in one atomic deployment. Do not mix a new
preseed.cfg with an old payload or manifest. The tarball is an installer source
release, not an in-place repair program for an already running desktop. Preserve
existing local installer inputs/secrets and review them before replacing a
production serving directory. Do not copy the entire hooks tree over a live `/`.

On a disposable validation host, the existing offline entry points are:

```sh
python3 -B tools/build.py --check
python3 -B tools/check_preseeds.py
python3 -B tools/check_shells.py
python3 -B -m unittest discover -v -s d-i/forky/tests -p 'test_installed_failures_20260911.py'
# With the repository's full external test dependencies installed:
python3 -B tools/validate.py --output-dir /tmp/debian-preseed-validation
```

After an unattended target installation, collect firstboot stage diagnostics,
then test a fresh desktop login, portal activation, both available GPU launch
modes, KWallet creation/unlock/save, Tuta credential storage, Bitwarden login and
SSH-agent actions, Recoll preview/indexing, icon/theme loading, Bluetooth,
Podman shutdown and network teardown. This is the remaining acceptance gate.

Useful read-only diagnostics (run user commands inside the desktop account):

```sh
systemctl --failed
systemctl status firstboot.service --no-pager
sudo cat /var/lib/installer-state/logs/firstboot/status.env
sudo cat /var/lib/installer-state/logs/firstboot/20-firstboot.log
sudo cat /var/lib/installer-state/logs/firstboot/data/validation-results.txt
systemctl --user --failed
systemctl --user status labwc-kwallet-portal.service xdg-desktop-portal.service --no-pager
namei -l /usr/local/share/icons "$HOME/.config/kwalletrc"
stat -c '%U:%G %a %n' "$HOME" "$HOME/.config" /etc/default/labwc-desktop /usr/bin/systemd-run
sudo journalctl -b -k --no-pager | grep 'apparmor=' || test "$?" = 1
```

Before relying on repaired Bitwarden updater caches on an existing deployment,
use the normal download-then-update workflow with the patched updater. Unmarked
old retained archives are deliberately not installable as trusted vendor copies.
No wallet, vault, keyring or application-state deletion is prescribed.
