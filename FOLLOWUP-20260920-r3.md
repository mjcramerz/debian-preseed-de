## Orange highlighting in all five native menus

The shared menu stylesheet uses `rgba(242, 159, 103, 0.24)`: a restrained orange overlay on the existing dark panel. Enabled menu items and submenu headers use the same orange background for pointer hover and keyboard selection, with the existing cream foreground (`#f5efe3`). The rule also explicitly colors the label nodes so a theme's selected-text color does not lower contrast.

The selectors apply directly to GTK `menuitem` nodes in Waybar's own stylesheet. They are deliberately not constrained to descendants of `window#waybar`, because GTK popup menus are separate windows. They do not modify the system-wide GTK theme.

Both `:hover` and `:selected` are covered. GTK represents native menu selection using the PRELIGHT state, which maps to `:hover`; the additional `:selected` rule handles that state consistently when exposed. Disabled items are excluded from the orange rule and retain a transparent background and the muted text color (`#aeb7c6`). This is important for the optional Whisper submenu: an unavailable feature must not look actionable.

No menu structure, separators, gestures, launch arguments, padding, or module layout was changed to achieve the new color.

## Open notifications center: wiring and availability fix

The first notifications menu item now has the requested visible label and retains ID `notifications_center`. In both rendered bars, that ID maps through the existing managed transient-service wrapper to:

```text
/usr/local/libexec/labwc-notifications center
```

The notifications button's right-click shortcut targets the same helper/action. Left-click opens the seven-entry native menu, and middle-click retains the existing DND toggle. Opening the center does not implicitly dismiss, restore, or change DND.

The center's existing implementation was preserved: a Wayland-only, single-instance `Gtk.Application` identified as `org.labwc.NotificationCenter`, on the validated user's runtime/bus, with Current and History tabs, refresh, DND, dismiss, and restore controls. Its bounded requests, plain-text notification rendering, partial-error handling, cached rendering, worker cancellation, exact-child cleanup, and shutdown behavior were not rewritten. All seven helper definitions other than `main` are AST-identical to revision 2; the GUI definition itself is unchanged.

### Corrected hidden-button failure

Revision 2 emitted valid fallback JSON when `status` failed but then exited with code 1. Waybar's custom-module implementation hides the widget when its command exits nonzero, even when stdout contains JSON. As a result, a Mako/service/runtime failure could remove the very button needed to open the center and see what was wrong.

For the exact `status` invocation only, the helper now emits one bounded JSON object with a nonempty icon, `class: error`, a clear **Notifications unavailable** explanation, and the usual mouse guidance, then exits 0. This means the status object was delivered, not that Mako succeeded. Diagnostics still go to stderr. Normal polling can replace the error state after recovery.

The exception is intentionally not generalized: DND, restore, dismiss, clear, center startup failures, and malformed invocations still return nonzero. Privileged-user and unsafe-runtime checks still run before backend access; the new status fallback does not grant control access. Tests explicitly cover these distinctions, malformed arguments, unavailable/permission-denied/timed-out backends, ordinary/DND status, and rejection of inherited X11, module-injection, and alternate-bus variables.

The matrix covers all 13 profiles, both bar layouts, Adwaita and Adwaita-dark, and optional Whisper enabled/disabled. It loaded 520 menu roots and checked 14,820 enabled highlight states, 5,096 disabled states, and 624 submenu-header instances. ## Deployment and disposable-target acceptance

Publish the complete repository atomically. Do not mix the new `preseed.cfg` with an old payload or manifest. Replacing the server's codebase affects subsequent installations; it does not automatically rewrite existing users' live Waybar files. For an existing machine, use the established deployment/update procedure to publish the rendered stylesheet and notifications XML and the helper, then restart Waybar at an appropriate time; do not copy the unresolved `.tmpl` file as a live configuration.

On a disposable target running the requested stack, verify the following before production rollout:

1. Open all five menus using the gestures above on both outputs. Hover each enabled item and traverse nested Tomat, calendar, and Whisper entries with the keyboard. Enabled selections should be orange-tinted, labels readable, and disabled Whisper unavailable without a misleading highlight. The notification/lock/power button colors and native drawer images should remain as in revision 2.
2. Choose **Open notifications center** and then invoke it again via the right-click shortcut. The same usable center should be presented, with no extra persistent viewer or unmanaged X11 process. Check Current/History, refresh, Escape/close, reopening, and the user journal for import, bus, or display errors.
3. With disposable notifications, exercise the three DND actions, dismiss-to-history, restore, and discard-active-without-history. Verify expected behavior with DND both on and off. Opening the viewer itself must not mutate notifications. Existing history is not erased by the discard-active command.
4. In the disposable session only, make Mako temporarily unavailable and verify the notifications button stays present, its tooltip reports unavailability, and the viewer remains responsive with unavailable views. Restore Mako and check normal status recovery. Inspect the user journal and AppArmor audit records rather than disabling confinement.
5. Exercise calendar/task commands with disposable data and configured accounts; test cancellation paths as well as success. Test timer preferences/presets, audio controls, and optional Whisper only where the add-on is installed. Power commands were not changed in this revision; retain revision 2's dedicated disposable-system shutdown acceptance checks rather than triggering them on a working desktop.

- [GtkMenuShell](https://docs.gtk.org/gtk3/class.MenuShell.html): native selection, activation, and submenu semantics.
- [Waybar 0.14.0 native-menu implementation](https://raw.githubusercontent.com/Alexays/Waybar/0.14.0/src/ALabel.cpp): GtkBuilder root/item lookup, configured action callbacks, and synchronous callback execution. This is a reviewed upstream reference, not a new package pin.
- [Waybar 0.14.0 custom module](https://raw.githubusercontent.com/Alexays/Waybar/0.14.0/src/modules/custom.cpp): `Custom::update` hides nonzero-status output; JSON handling and subsequent refresh behavior.
- [GApplication](https://docs.gtk.org/gio/class.Application.html): application identity and session-bus activation/uniqueness semantics used by the preserved viewer.
- [Mako 1.11 control implementation](https://raw.githubusercontent.com/emersion/mako/v1.11.0/makoctl.c) and [Mako control manual](https://raw.githubusercontent.com/emersion/mako/master/doc/makoctl.1.scd): JSON listing/history and the distinct dismiss, discard, restore, and mode operations.
